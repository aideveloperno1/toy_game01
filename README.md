# 복불복 — 내기 게임 모음

친구들과 내기할 때 당첨자·꽝을 정하는 모바일 웹앱입니다. **한 기기로 하기**와 **각자 폰으로 방에 접속하기**를 지원합니다. 온라인은 로그인 없이 닉네임·초대 링크·QR로 참가합니다. 한 기기 모드는 오프라인에서도 동작하고, 온라인 방은 서버 연결이 필요합니다.

온라인 방은 사다리·룰렛·동물 경주·카드·해적 통·폭탄·스크래치·10초 맞추기·구슬 레이스 9종을 지원합니다. 손가락 뽑기는 한 기기 전용입니다. 서버가 차례·제한 시간·결과를 관리하고, 숨겨진 배치는 클라이언트에 전달하지 않습니다.

온라인 규칙·저장·Azure 설정·배포 및 복구 방법은 [운영 문서](docs/OPERATIONS.md)를 참고하세요.

## 게임 10종

| 게임 | 방식 | 인원 |
| --- | --- | --- |
| 사다리타기 | 같이 보기 | 2~12명 |
| 룰렛 | 같이 보기 (탈락식) | 2~20명 |
| 구슬 레이스 | 같이 보기 (물리 시뮬레이션, 맵 3종) | 2~30명 |
| 동물 경주 | 같이 보기 (역전·사진 판정 연출) | 2~12명 |
| 카드 뒤집기 | 돌아가며 | 2~20명 |
| 폭탄 돌리기 | 돌아가며 (폰을 옆 사람에게) | 2~12명 |
| 스크래치 복권 | 돌아가며 | 2~20명 |
| 해적 통 | 돌아가며 | 2~12명 |
| 10초 맞추기 | 실력 | 2~20명 |
| 손가락 터치 뽑기 | 이름 없이 즉석 (홈 화면) | 2~10명 |

모든 게임에서 결과 방식을 고를 수 있습니다.

- **꽝 / 당첨:** K명에게 꽝(벌칙) 또는 당첨(좋은 결과)
- **항목 나누기:** "밥값 1, 커피 2"처럼 항목별로 배정, 나머지는 통과
- **전체 순위:** 1등부터 N등까지

그 밖에 멤버를 모임으로 저장해 다음에 바로 불러오기, 최근 50판 기록과 모임별 벌칙 횟수, 같은 판 다시 보기, 결과 이미지 공유, 게임 랜덤 선택, 소리·진동, 다크·라이트 테마를 지원합니다.

## 공정성

- 게임을 시작하는 순간 Web Crypto로 32바이트 seed를 만듭니다. 추첨형 게임은 결과를 먼저 정하고 화면에서 연출합니다. 카드·해적 통은 배치를 먼저 정한 뒤 실제 선택으로 결과가 정해지고, 10초 맞추기는 측정 기록으로 순위를 정합니다.
- 판 번호의 짧은 표시(예: `#A3F9`)는 게임 중과 결과 화면에 모두 나옵니다.
- 카드 뒤집기·해적 통처럼 직접 고르는 게임은 배치를 시작 전에 정해둡니다. 해적 통의 구멍 수는 남은 인원의 배수라 모두 같은 횟수만큼 꽂습니다.
- 폭탄 돌리기는 꽝이 될 사람을 먼저 정하고 그 사람 차례에 터집니다. 15초 넘게 들고 있으면 자동으로 넘어가고, 그래도 결과는 바뀌지 않습니다.
- 구슬 레이스는 번호만 붙은 구슬로 시뮬레이션한 뒤 "p번째 도착 구슬 = 순위 p번째 사람"으로 이름을 붙입니다. 맵의 유불리가 결과에 영향을 주지 않습니다.
- 같은 멤버로 5분 안에 다시 하면 "재경기 N회차"가 표시됩니다.

`tests/fairness`의 자동 테스트가 게임별로 10만 회씩 시뮬레이션해 각자의 꽝 확률이 K/N ±1% 안인지(카이제곱 검정 포함) 확인합니다. 참여형 게임은 "항상 첫 칸 / 항상 끝 칸 / 무작위" 세 가지 선택 전략으로 각각 확인합니다.

## 실행

Azure API와 동일한 Node.js 22 LTS(22.12 이상)를 사용합니다.

```bash
npm ci
npm run dev      # 웹 화면(5173) + 방 서버(3001). 같은 Wi-Fi에서는 Network 주소 사용
npm run build    # dist/ 화면 + api/dist/ Azure API + dist-server/ 로컬 API 생성
npm test         # 공정성 + 온라인 판정/동시 저장/복구/HTTP 테스트
npx playwright install chromium
npm run test:e2e # 독립 모바일 브라우저로 온라인 9종 실제 진행
npm start        # 개발·검증용 로컬 서버 (기본 3001)
npm run dev:local # 웹 화면만 개발. 온라인 서버가 없으면 방 기능 사용 불가
```

## 배포 (Azure Static Web Apps)

화면과 HTTP API는 **Static Web Apps의 기본 관리형 Functions**로 배포합니다. 방과 비공개 경주 데이터는 **Azure Blob Storage**, 실시간 변경 알림은 **Azure Web PubSub**를 사용합니다. 별도 App Service는 필요하지 않습니다. SWA의 Free 플랜도 API를 지원합니다.

GitHub 연결만으로 외부 저장소와 실시간 서비스의 키가 자동 설정되지는 않습니다. SWA의 API 환경 변수에 `GAME_STORAGE_CONNECTION_STRING`, `WEB_PUBSUB_CONNECTION_STRING`, `SESSION_SECRET`을 설정해야 합니다. 설정이 없으면 방 기능은 명확한 오류를 반환하며 임시 저장으로 넘어가지 않습니다.

`deploy.yml`이 빌드·테스트 후 배포 파일을 만들고, 성공하면 같은 workflow의 배포 단계가 SWA에 배포합니다. GitHub Secret `AZURE_STATIC_WEB_APPS_API_TOKEN`이 있을 때 자동 배포가 활성화됩니다. Azure가 별도로 생성한 배포 workflow가 있으면 중복되지 않게 하나만 사용하세요. 새 리소스 템플릿은 `infra/main.bicep`, 기존 리소스 연결 및 상세 검증은 [운영 문서](docs/OPERATIONS.md)에 있습니다.

실시간 연결이 끊겨도 HTTP 동기화로 게임을 이어갑니다. 기본 HTTP API는 상시 타이머를 실행하지 않으므로 마감 처리는 접속자의 다음 동기화 요청 때 확정됩니다. 모두 나가면 다음 접속에서 경과 시간을 판정하고, 10분간 전원 부재하면 방을 닫습니다.

## 구조

```
src/
├─ core/          # 게임과 무관한 추첨 엔진 (rng.ts, draw.ts, types.ts)
├─ store/app.ts   # 화면 상태, 참가자, 모임, 기록, 설정 (localStorage 저장)
├─ screens/       # 홈, 참가자, 결과 정하기, 게임 고르기, 진행, 결과, 기록, 설정, 손가락 뽑기
├─ games/
│  ├─ registry.ts # 게임 목록. 새 게임은 폴더 하나 + 여기 한 줄
│  ├─ _kit/       # 차례 넘기기 화면, 연타 방지, 결과 색 등 공통 부품
│  └─ <게임>/     # 게임별 화면 + 순수 로직(logic.ts)
├─ lib/           # 효과음(Web Audio 합성), 진동·화면 꺼짐 방지, 공유 이미지
└─ styles/
tests/fairness/   # 공정성 테스트
```

## 기획서 대비 달라진 점

- 효과음은 음원 파일 대신 Web Audio로 합성합니다. 라이선스 확인이 필요 없고 용량이 0입니다. 그래서 Howler.js를 쓰지 않습니다.
- 애니메이션은 CSS와 requestAnimationFrame으로 처리해 Motion 라이브러리를 쓰지 않습니다.
- 기록은 50판 규모라 IndexedDB 대신 localStorage에 저장합니다.
- 제목용 글꼴은 Pretendard 대신 둥근 손글씨 느낌의 Jua를 쓰고, 본문은 기기 기본 글꼴을 씁니다. 글꼴은 쓰는 글자 조각만 내려받아 저장합니다.
